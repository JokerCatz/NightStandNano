# libadplug patches

`0001-adplug-trim-and-hardening.patch` is a unified diff of every vendored AdPlug 2.4 file that differs from the release (`diff -u pristine ours`, paths relative to `adplug/`). Files that exist only here: `players_table.cpp/.h`, `adplug_c.cpp/.h`, `database.h` replaces the original, `debug.c/.h` and the rest are pristine. Every edit in the sources is marked `libadplug patch 0001`. Groups:

1. Trim: no file-system provider (`fprovide.cpp`), no database (`player.cpp`, `imf.cpp`, `database.h`), A2M v9-11 refused (`a2m-v2.cpp`, aPlib has no licence), `strnlen.h` (the original defined `__STDC_WANT_LIB_EXT1__` mid-file, which breaks picolibc's headers).
2. Hardening found by fuzzing the real DOS files (`test_opl`, ASan + UBSan, `OPL_FUZZ=12`): an index, bound or loop limit each in `cmf`, `hybrid`, `msc`, `coktel`, `herad` (decompressors, instrument and note indexes), `bam`, `xsm`, `protrack`, `unlzh` (unaligned load: RISC-V faults; table and code-length overruns), `lds`, `hsc`, `hsp`, `mus`, `a2m-v2` (never-NULL instrument, a leak), `plx` / `mkj` / `sixdepack` / `cmf` (an `assert` that a damaged file could trip became a clamp; the component builds with `-DNDEBUG`).
3. Not exhaustive: AdPlug's players trust their input. A heavier fuzz run (`OPL_FUZZ=40` or another seed) may find more; each finding is one more index check here.

`0002-binio-h-configured.patch`: `binio.h.in` with the configure substitutions (string yes, iostream no, ISO stdlib, math, `int`, `double`).

## Fuzz hardening (OPLFUZZ, 2026-11-18; harness: tools/bench/opl_fuzz, README there)
Diffs against the tree at viz-page f5230d5; adplug_c.cpp / adplug_c.h / pc_backend_opl.c are ours and not in these diffs (their changes: the allocation list + longjmp, the per-call jump context, the tick-rate clamp, the scan wall-clock budget ADP_SCAN_MS, ADP_ERR_DAMAGED).
- `0003-central-guard-and-first-fixes.patch`: libbinio `binstr` (integer seek, sticky `pastend`, `adp_eof_overrun()` after 262144 reads past the end), a2m-v2 / mid `calloc`/`free` into the handle's allocation list (`adp_tcalloc`/`adp_tfree`), dmo (file < 32 bytes), bam (no-wait song), mid (meta/sysex length clamp), u6m (command guard).
- `0004-fuzz-hardening-groups.patch`: the four extension groups' fixes, marked `libadplug patch 0004` (rad2, bam, sixdepack, composer, coktel, a2m-v2), `0005` (protrack, mus, mdi, composer, ksm, d00, mkj, mid, u6m), `0006` (protrack, lds, u6m), `0007` (msc, pis, u6m, herad, sng, xsm, sop), `0008` (rad2 jump marker / Tracks index). One line per fix is in the OPLFUZZ report.
- Regression tests: `host_test/test_opl_hostile_{0,a,b,c,d}.c` (inputs built in the test).
- `0009-typed-stl-allocator.patch`: `adplug/adp_alloc.h` (an STL allocator type that allocates through adplug_c.cpp's per-handle list) used by the players' vectors and stacks (rol.h, composer.h, cmfmcsop.h, u6m.h/.cpp), so no instantiation of ours can be merged with another translation unit's std::vector.
- No global `operator new` / `delete` is replaced (OPLFUZZ 3): `adplug_scope.cmake` renames, with objcopy on the component's own archive, the operator new / delete symbols its objects reference to `adp_op_*` (adplug_c.cpp: header with a magic word, per-handle list, 8 MiB / 16 MiB caps, failure = longjmp to the API call, no abort), and fails the build if one is left undefined. A pointer without the magic word (a std::string buffer that libstdc++ allocated) goes to `free()`. The rest of the image (GME, ...) keeps the toolchain's operator new; verified in the ELF (`_Znwj` and `adp_op_Znwj` are different functions).

## CHIPFIX (2026-11-18)
- `adplug/fmopl.c`, marked `libadplug patch chipfix` (a diff is the git history of that commit): `OPLOpenTable` reads its tables from `adplug/fmopl_tables.h` (generated by `tools/gen/gen_fmopl_tables.py`, checked by `make lint-app`; the values are the original double `pow` / `sin` / `log10` results, bit-identical, 8200 soft-double libm calls less per open on the S31); the rhythm-mode noise bit is a private xorshift32 (reset with the chip) instead of libc `rand()`.
- `adplug_c.cpp`: the silent length scan accumulates microseconds from a float divide instead of a double.

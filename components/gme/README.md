0008-nsf-fds-mmc5-vrc7-meters.patch (CHIP2A, 2026-11-17): level accessors for the NSF expansion chips that had none, so the voice meters show them: `Nes_Fds_Apu::osc_last_amp`, `Nes_Vrc7_Apu::osc_last_amp` and `Nsf_Emu::fds_() / mmc5_() / vrc7_()` (MMC5 is a Nes_Apu: its squares and PCM already had `osc_last_amp`). Read-only, no change to what is rendered. The meter code is in app/main/backend_gme.cpp `level_nes`.
0009-kss-msx-music-fm.patch (CHIP2A): Kss_Emu captures the MSX-MUSIC port writes ($7C/$7D) and renders them through the Ym2413_Emu (emu2413) into a ring that play_ mixes in; on by default since 2026-11-18 (project decision after board run 3: 33-37 % of core 1, 0 underruns; zero-init `Kss_Emu::fm_off`, switched through `backend_gme_kss_fm()` / console `kssfm off`).
0010-emu2413-fixed-point.patch (OPLL, 2026-11-17): emu2413 fast enough for the board (single-precision FPU only, double is software): the rate converter keeps the same 16-tap windowed sinc but its position is exact integer arithmetic (no double per sample; the table is built in float, identical to the double one at 44.1 / 48 / 96 kHz), the history is a doubled ring (no memmove), the x72-scaled sample clock is int64; default pan mixes once for both sides; per-slot caches of the phase increment, envelope mask and an "envelope idle" flag; the 18 noise LFSR steps per sample in closed form. Two upstream bugs fixed, both also fixed in upstream v1.6.3 (which still uses double, so not vendored): the converter's shared timer advanced on every getData call (in stereo L and R read the history at wrong, different positions: 14-37 dB SNR against the fixed output on the test VGM / KSS), and commit_slot_update returned early at rate 0 with its requests still set (every idle slot recomputed its tables on every sample). MSX-MUSIC in KSS (0009) is now on by default: `Kss_Emu::fm_wanted` became `Kss_Emu::fm_off` (zero-initialised, so the flag stays in .bss: a true-initialised bool moved to .data and cost 8 B of DIRAM alignment)
Obsolete since 2026-11-18 (history only, NOT applied): 0005-emu2413-flash-tables.patch and 0010-emu2413-fixed-point.patch edited gme/ext/emu2413.c, which is gone; the fork carries the same ideas (const tables, no double, slot caches, converter fixes). The rest of 0010 (Kss_Emu `fm_off`, MSX-MUSIC on by default) stays in gme/. The glue (Ym2413_Emu.cpp, Nes_Vrc7_Apu.cpp) uses only OPLL_new/reset/resetPatch/setChipType/writeIO/setMask/calcStereo/delete and `ch_out`, which are the same in 1.6.x, so it needed no API adaptation beyond the include (`emu2413.h`); setPatch / dumpToPatch / copyPatch / save-state are not used by GME. emu2413 files in the old OPLL numbers (sum=) changed: the core is upstream 1.6.4.
0011-ym2413-idle-skip (INV, 2026-11-18, applied directly in Ym2413_Emu.cpp/.h, no patch file): the glue skips the samples of an OPLL that cannot sound (all carriers muted, nothing to commit) and advances its clocks exactly. Bit-identical to calculating them unless an unmuted modulator with feedback froze; see the comment above opll_silent. Test: test_ym2413_idle_skip (host_test/ym2413_shim.cpp).
0012-ym2413-clock-bound.patch (FIX6, 2026-11-18, wave-6 review + fuzz): `Vgm_Emu::setup_fm` refuses a YM2413 header clock outside 1..8 MHz (at 0x3FFFFFFF emu2413 ran about 340 chip steps per output sample), a clock of 0 stays silence; `Ym_Emu::run_until` returns false first for a chip the header did not enable (a 0x51 command with YM2413 clock 0 wrote into a NULL OPLL); an SN76489 clock below 100 kHz means the default (200 Hz tripped a Dual_Resampler assert).
0013-vgm-truncated-commands-ym2612-clock.patch (FIX7, 2026-11-18, wave-6 fuzz): `Vgm_Emu_Impl::run_commands` checks the bytes a command needs before it reads them (a command cut off by the end of the data ended up to 11 bytes past it; the upstream TODO), a data block longer than the data and a PCM seek or read outside it end the stream / give silence; `Vgm_Emu::setup_fm` refuses a YM2612 clock that is not above the FM sample rate (`Ym2612_GENS_Impl::build_tables` asserts it, which aborts the firmware); the YM2612 attack/decay rate tables clamp each step to one whole envelope (a hostile clock overflowed them into a negative envelope counter: out-of-range ENV_TAB read in `ym2612_update_chan`). `Sms_Apu::reset` (the VGM header's SN76489 shift width went into `1 << (width - 1)`: UB above 31) falls back to the default outside 1..31. Test: test_gme_voices `test_vgm_truncated_commands`, `test_vgm_hostile_ym2612_clock`, `test_vgm_sn76489_shift_width`.
